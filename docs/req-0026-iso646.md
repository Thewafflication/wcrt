# REQ-0026 — Alternative operator spellings

**Content type:** Project requirement

**Status:** Implemented

**Source:** ISO/IEC 9899:1999 §7.9

## Scope

This requirement adds the C95 `<iso646.h>` interface inherited by C99.

## Requirement

- In C99 and later modes, WCRT's self-contained `<iso646.h>` shall define
  `and`, `and_eq`, `bitand`, `bitor`, `compl`, `not`, `not_eq`, `or`, `or_eq`,
  `xor`, and `xor_eq` as macros for their corresponding operator tokens.
- Each macro shall preserve the precedence, associativity, operand evaluation,
  result type, and side effects of its corresponding operator token.
- The header shall be safe for repeated inclusion and shall introduce no
  declarations, objects, or runtime dependencies.
- Selecting the C89 library surface shall not expose these macros through a C89
  header.

## Rationale

C99 incorporates the C95 amendment, making this small header part of the C99
library baseline rather than an optional compatibility extension.

## Verification

**Method:** Automated compile-time and behavioral test

**References:** `TC-0026`

TC-0026 shall verify every macro's spelling and operator equivalence, precedence,
single operand evaluation, self-containment, repeated inclusion, and C89-mode
isolation.

## Relationships

- **Derived from:** C99 Milestone 2A and the C95 amendment
- **Depends on:** Public-header edition selection
- **Conflicts with:** Defining the spellings as functions or non-equivalent text

## Tailoring

This header is required in C99 and later modes and has no runtime allocation.

## Implementation Record

`include/iso646.h` defines all eleven alternative operator spellings when the
C95-or-later surface is selected and honors the explicit `WCRT_C89` selector.
TC-0026 checks self-containment, repeated inclusion, truth and bit patterns,
assignment spellings, precedence-sensitive expressions, short-circuit side
effects, and direct C89 isolation.
